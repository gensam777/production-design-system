# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this is

A production-style design system — design tokens, components and Storybook documentation —
web-first (React) and growing to React Native, iOS (SwiftUI) and Android (Compose) in one
repo (ADR 0013). Plain **npm workspaces** since Phase 4 (ADR 0017); no other monorepo
tooling. Meant to also serve as a template for future app projects.

## Structure

```
design/                 # platform-neutral source — no platform code
  tokens/               # token source: core/, brands/<brand>/, semantic/, platform/{web,native}/
  fonts/                # font asset catalog fonts.json + schema (metadata, not tokens; ADR 0016)
  contracts/            # schema.json + components/*.contract.yaml (ADR 0015)
  icons/                # icons.json + schema — platform-neutral icon catalog (DS name → Lucide, pinned version; ADR 0019)
packages/               # npm workspaces
  tokens/               # @pds/tokens — token build pipeline (scripts/), tests, generated build/ (gitignored: IR, web CSS/JS, RN TS)
  react/                # @pds/react — the web design system
    src/
      components/       # React components (exported from index.ts)
      patterns/         # documented pattern/template compositions — NOT exported (see docs/patterns/)
      examples/         # product example screens built from components + patterns (not exported)
      icons/            # Icon + IconName catalog (ADR 0010)
      index.ts          # public entry point / barrel export
    .storybook/         # Storybook config
  react-native/         # @pds/react-native — RN components (Button alpha), PDSThemeProvider; Jest + RNTL in __tests__/
  react-native-example/ # @pds/react-native-example — Expo SDK 58 preview app (Brand A/B Button gallery); not a library
platforms/
  ios/Sources/PDSTokens/    # generated Swift tokens (committed)
  ios/Sources/PDSUI/        # SwiftUI components (DSButton alpha); Icons/ generated by `npm run icons:swift`
  ios/Tests/PDSUITests/     # Swift Testing (`swift test`)
  android/              # Gradle build (open THIS folder in Android Studio; ./gradlew): tokens/ (com.pds.tokens, generated Kotlin, committed); compose/ (com.pds.compose — DsButton alpha; icons/ generated by `npm run icons:kotlin`)
Package.swift           # Swift package (repo root so SwiftPM can resolve it by git URL)
docs/                   # design-to-code-mappings.md + foundations/ + patterns/ + cross-platform/ documentation
governance/             # accessibility, lifecycle, versioning rules + ADRs (decisions/)
scripts/                # repo tooling: token-usage guardrail, contracts/ (validator), design-audit/ (Figma ↔ code drift audit)
.claude/skills/         # custom Claude Code skills (component-production, design-audit, figma-screen-sync, token-production, pattern-production)
```

## Source of truth

- **Figma** = design intent (what something should look like).
- **`design/tokens/{core,brands/*,semantic,platform/{web,native}/*}/*.json`** = shipped token
  values, authored platform-neutral (px numbers, hex/hex8, family names — no CSS syntax; ADR
  0014; web-only tokens in `platform/web/`, native-only text-scaling anchors and Android
  elevation in `platform/native/`, ADR 0016). `design/fonts/fonts.json` is the font asset
  catalog (metadata, not tokens; no font files). Figma should mirror
  these; if they disagree, code wins for anything already released.
- **Multi-brand**: components consume semantic tokens only and never know the brand; brands
  differ only in the `brand.*` contract (primary ramp, sans family, control/container radius).
  Runtime switch: `data-brand="brand-a|brand-b"` on `<html>` or any container; no attribute =
  Brand A. See `docs/foundations/theming.md` and ADR 0011.
- **React (`packages/react/src/components/`)** = component behavior and public API.
- **Storybook** = the coded documentation of how components actually behave — treat a
  story as more authoritative than a written description if they conflict.
- **`docs/design-to-code-mappings.md`** = manually maintained map from Figma components
  to React components. There is no automated sync (Figma Code Connect is not used) —
  update this file by hand whenever a component ships.

## Commands

Root scripts delegate to the workspaces (`npm run <script> -w @pds/<pkg>`); run them from the
repo root.

- `npm install` — installs and links the workspaces (`@pds/tokens`, `@pds/react`,
  `@pds/react-native`, `@pds/react-native-example`) into `node_modules/@pds/`. One React
  (19.3.0, Expo SDK 58 / React Native 0.88) is shared by every workspace — `react-dom` must
  stay the exact same version. The React Native workspaces need Node ≥ 22.13.
- `npm run build` — builds `@pds/tokens`, then the React library (tsup) →
  `packages/react/dist/` (`@pds/react` exports `.` and `./index.css`; token CSS is bundled in)
- `npm run typecheck` — `tsc --noEmit` in every workspace that has a `typecheck` script
  (`@pds/react`, `@pds/react-native`, `@pds/react-native-example`; the RN ones need
  `npm run tokens:build` first)
- `npm run test:react-native` — Jest + React Native Testing Library for `@pds/react-native`
  (Button behavior and accessibility, contract token parity in both brands; needs
  `npm run tokens:build` first). Runs in CI.
- `npm run example:react-native` — `expo start` for the preview app;
  `npm run example:react-native:export` bundles it for iOS + Android (`expo export`, no native
  toolchain; builds tokens first) → `packages/react-native-example/dist/`. Runs in CI.
- `npm run lint` — ESLint (includes `eslint-plugin-jsx-a11y`) + `scripts/check-token-usage.mjs`
  (components/patterns/examples and `packages/react-native{,-example}/src` may not use Core
  primitives, `--brand-*`, or raw hex colors; documented exceptions only via
  `scripts/token-usage-exceptions.json`)
- `npm run format` / `npm run format:check` — Prettier
- `npm run tokens:build` — `packages/tokens/scripts/build.mjs`: resolves each brand over
  `design/tokens/{core,brands/<brand>,semantic}` + the platform tiers `design/tokens/platform/{web,native}/`
  into a platform-neutral IR (`packages/tokens/build/ir/<brand>.json`, `packages/tokens/scripts/ir.mjs`, with
  the brand's font manifest derived from `design/fonts/fonts.json`), runs the guardrails on
  it (`packages/tokens/scripts/guards.mjs`), then the emitters: web CSS/JS (`packages/tokens/scripts/emit-web.mjs`
  + `packages/tokens/style-dictionary.config.mjs`) and, via the native model (`packages/tokens/scripts/native.mjs`,
  semantic tokens only), React Native TS (`build/react-native/`), Swift `PDSTokens`
  (`platforms/ios/Sources/PDSTokens/`) and Kotlin `com.pds.tokens`
  (`platforms/android/tokens/src/main/kotlin/com/pds/tokens/`) (ADR 0014, 0016, 0017 — the
  Swift and Kotlin outputs are **committed** sources, everything in `build/` is gitignored and
  served through `@pds/tokens`' exports, e.g. `@pds/tokens/css/variables.css`). Fails on an
  incomplete brand contract, a platform tier overriding a shared token, a shared token aliasing
  a platform-only token, a shared token that differs between brands, a per-brand contrast pair
  below WCAG minimums, an invalid font catalog / missing face, or a missing native mapping
  (text-scaling anchor, Android elevation). Brand-dependent tokens go to `css/brands/<brand>.css`
  (ADR 0011); shared CSS is split across three files: `css/variables.css` for most tokens
  (colors, typography primitives, spacing, radius, elevation, motion),
  `css/typography.css` for the expanded composite typography roles (see
  `governance/decisions/0003-typography-token-architecture.md`), and
  `css/motion-reduced-motion.css` for the `prefers-reduced-motion` override (see
  `governance/decisions/0008-motion-token-architecture.md`))
- `npm run tokens:test` — every token output (8 web files, RN, Swift, Kotlin) vs its committed
  copy — web + RN in `packages/tokens/__tests__/__snapshots__/` (web must stay byte-identical),
  Swift/Kotlin in `platforms/` — plus IR ↔ native parity, RN strict type-check, design-audit
  resolver ↔ IR parity, guardrail negative tests. Runs in CI, which also builds the Swift
  package (`PDSTokens` on Linux; `PDSUI` tests + iOS Simulator build on macOS) and the Gradle
  project. After a reviewed
  output change: `npm run tokens:test:update`. A token change must commit the regenerated
  `platforms/` sources (CI fails on a diff after `tokens:build`).
- `npm run design:audit` — Figma ↔ code design-drift audit (detection/reporting only) for the
  Login surface, against the **committed** Figma snapshot in `scripts/design-audit/snapshots/`.
  Offline + deterministic; exit 1 on DRIFT/ERROR; runs in CI. It cannot see Figma edits made
  after the last snapshot refresh — refresh via the `design-audit` skill. See
  `docs/design-audit.md`. Tests: `npm run design:audit:test`; snapshot import/validate:
  `npm run design:audit:snapshot -- <import <raw.json>|validate>`
- `npm run contracts:validate` — validates every `design/contracts/components/*.contract.yaml`
  (ADR 0015): JSON Schema, no platform API names (`className`, `href`, `aria-*`, `ReactNode`,
  `onPress`, `Modifier`, …), token paths semantic + shared in every brand's IR, Figma axes ↔
  enums + committed design-audit snapshots, and the web / React Native / iOS references (enum
  unions or Swift enums, defaults, token set ↔ styles / token map). `npm run contracts:test` — negative tests for each check + Button's
  cell-by-cell CSS parity. Both run in CI.
- `npm run icons:test` — the icon catalog (`design/icons/icons.json`, ADR 0019) against its
  schema, the web and React Native `IconName` unions and Lucide maps, the installed
  `lucide-react` / `lucide-react-native` / `lucide-static` versions (must equal
  `provider.version`) and the committed SwiftUI icon sources. Runs in CI.
- `npm run icons:kotlin` — regenerates `platforms/android/compose/src/main/kotlin/com/pds/compose/icons/`
  (`DsIconName` + Lucide `ImageVector`s) the same way (commit the output).
- `npm run icons:swift` — regenerates `platforms/ios/Sources/PDSUI/Icons/` (`DSIconName` +
  Lucide SwiftUI paths) from the catalog and `lucide-static` (commit the output).
- `npm run storybook` — Storybook dev server (`@pds/react`)
- `npm run build-storybook` — static Storybook build → `packages/react/storybook-static/`
- Swift (macOS + Xcode): `swift test` at the repo root (`PDSUI` tests on the macOS host);
  `xcodebuild -scheme PDSUI -destination 'generic/platform=iOS Simulator' build`; review the
  SwiftUI previews by opening `Package.swift` in Xcode
  (`platforms/ios/Sources/PDSUI/Previews/DSButtonPreviews.swift`). Linux / CI-only:
  `swift build --target PDSTokens`
- Android (JDK 21+ and Android SDK 36 — Android Studio provides both): `cd platforms/android &&
  ./gradlew build` (`:tokens` + `:compose`: compile, lint, JVM + Robolectric unit tests);
  versions in `platforms/android/gradle/libs.versions.toml`. Review Compose previews by opening
  `platforms/android` in Android Studio (`compose/…/button/DsButtonPreviews.kt`).

## Conventions

- Token source files use the DTCG format (`$value`, `$type`, `$description`). Never
  hand-edit anything under `packages/tokens/build/` — it's generated.
- New components go in `packages/react/src/components/<ComponentName>/`, exported from
  `packages/react/src/index.ts`.
- Platform-neutral source (tokens, fonts catalog, contracts) lives in `design/` and never
  contains platform code. Workspace packages depend on each other by name (`@pds/tokens`), not
  by relative path.
- Every component needs a Storybook story before it can leave "Alpha" — see
  `governance/component-lifecycle.md`.
- Accessibility bar: WCAG 2.2 AA. Full checklist in `governance/accessibility.md`;
  `eslint-plugin-jsx-a11y` and `@storybook/addon-a11y` are the automated first pass, not
  the whole check.
- Governance policy text lives in `governance/*.md` — link to it, don't duplicate it here.

## Git workflow

- Trunk-based: short-lived branches off `main` (`feat/...`, `fix/...`, `docs/...`).
- Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`).
- Versioning is currently manual (see `governance/versioning.md`) — Changesets tooling
  is deferred, not yet wired up.

## Cross-platform (Phase 5 — reference implementations, in progress)

Phase 5 was approved 2026-10-12. Decided: platform versions and the Button contract questions
(ADR 0018 — iOS 17 / macOS 14 host, RN peer `>=0.81`, Android minSdk 23 / compileSdk 36 /
AGP 9.1 / Kotlin 2.2 / Compose BOM without Material; disabled rule, minimum height, 2px
spinner + `motion.spinner`, `action.*.on-color`) and the icon catalog (ADR 0019). Done: those
tokens, the catalog, the contract update, the web Button and the live Figma Button alignment
(2026-10-12: 48-variant Button Content with On-primary / On-danger tones, label Text Styles,
`icon/*`-bound icon and spinner sizes, minimum-height masters, 2px spinner ring, reference
`spinner/*` motion variables), and the React Native Button (`@pds/react-native`, contract
status `alpha`, 2026-10-19: `PDSThemeProvider`, Expo preview app) and the SwiftUI Button
(`PDSUI` `DSButton`, contract status `alpha`, 2026-10-19: `.dsTheme(_:)`, generated Lucide
paths, `#Preview` gallery) and the Compose Button (`com.pds.compose` `DsButton`, contract
status `alpha`, 2026-10-19: `PdsTheme`, generated Lucide `ImageVector`s, `@Preview` gallery,
Gradle wrapper + version catalog). Next: Switch (plan in `docs/cross-platform/migration.md`).

Web, React Native, SwiftUI and Compose all have components (native: Button only). Phases 1 (portable token source + IR), 2 (native
token outputs), 3 (component contracts) and 4 (npm workspaces + `design/` + native package
scaffolding, ADR 0017) are done: the build emits React Native, Swift
(`PDSTokens`) and Kotlin (`com.pds.tokens`) token outputs for both brands — semantic tokens
only, pure data (ADR 0016; Android elevation provisional until Phase 5) — and
`design/contracts/` holds the JSON Schema plus per-component YAML contracts (ADR 0015; Button
only so far, `alpha` on web, React Native, iOS and Android). Contracts carry shared semantic intent
only — no web DOM props and no native API names, enforced by `npm run contracts:validate`.
A component with a contract must keep it in sync with its React implementation (the
component-production skill does this) and with every implemented native one
(`contracts:validate` checks the React Native, iOS and Android references too); see
`docs/cross-platform/`.
Share semantic intent, contracts and tokens — never convert React components or DOM props to
other platforms. No font files are bundled on any native platform. Web CSS/JS output must stay
byte-identical unless a change is intentional and reviewed (`npm run tokens:test` enforces it).
